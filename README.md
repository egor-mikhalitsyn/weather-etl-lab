# Weather ETL — прогноз погоды на четыре дня

Лабораторная работа по Python: автоматическое определение местоположения по IP,
получение прогноза OpenWeatherMap на сегодня и три следующих дня, агрегация
трёхчасовых интервалов, сохранение в SQLite и выгрузка в Markdown.

## Технологии

- Python 3.11+
- `requests` — HTTP-запросы к OpenWeatherMap и IP Geolocation API
- `SQLAlchemy` 2.x — ORM и транзакции SQLite
- `python-dotenv` — загрузка переменных из `.env`
- `logging` — журнал работы в консоли и файле
- `unittest` — автоматические проверки

Геолокация по умолчанию запрашивается через `https://ipinfo.io/json`.
Прогноз — через `https://api.openweathermap.org/data/2.5/forecast` с параметрами
`units=metric` и `lang=ru`.

## Установка

Замените `YOUR_USERNAME` своим именем пользователя GitHub и при необходимости
измените название репозитория.

```powershell
git clone https://github.com/YOUR_USERNAME/weather-etl-lab.git
cd weather-etl-lab
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Для Linux и macOS активация окружения: `source .venv/bin/activate`.
Полный список внешних зависимостей находится в `requirements.txt`.

## Настройка

1. Зарегистрируйтесь на [OpenWeatherMap](https://openweathermap.org/api) и получите API-ключ.
2. Скопируйте шаблон: `Copy-Item .env.example .env` (Linux/macOS: `cp .env.example .env`).
3. Заполните `WEATHER_API_KEY` в `.env`. Если `.env` уже есть, отредактируйте его, сохранив текущие настройки.
4. Укажите путь к SQLite в `DB_URL`. Файл БД и его родительский каталог создаются автоматически.

Пример `.env` без настоящих ключей и паролей:

```dotenv
WEATHER_API_KEY=put_your_openweathermap_key_here
WEATHER_API_BASE_URL=https://api.openweathermap.org/data/2.5
GEO_API_KEY=
GEO_API_URL=https://ipinfo.io/json
GEO_API_FALLBACK_CITY=Kirov
GEO_API_FALLBACK_LAT=58.6035
GEO_API_FALLBACK_LON=49.6679
DB_URL=sqlite:///weather_lab.db
DB_USER=unused_for_sqlite
DB_PASSWORD=unused_for_sqlite
ENVIRONMENT=development
OUTPUT_FILE=weather_report.md
OUTPUT_DIR=data_weather
LOG_LEVEL=INFO
LOG_DIR=log
```

`DB_USER` и `DB_PASSWORD` читаются из окружения согласно заданию, но SQLite
не использует логин и пароль: подключение задаётся через `DB_URL`.
Ключи и пароли не записываются в исходный код.

При сбое геосервиса используется `GEO_API_FALLBACK_CITY`. Координаты резервного
города необязательны; без них погода запрашивается по имени города.
Если координаты указаны, задайте обе и проверьте соответствие резервному городу.
Для геосервиса с токеном настройте `GEO_API_URL` и `GEO_API_KEY`.

Переменные процесса имеют приоритет над `.env`. Относительные пути БД,
отчётов и логов разрешаются от корня проекта независимо от каталога терминала.

## Запуск

```powershell
python main.py
```

Последовательность работы:

1. Определение города и координат по IP либо выбор резервной локации.
2. Получение пятидневного прогноза с шагом три часа.
3. Группировка по местной календарной дате города и выбор периода «сегодня + 3 дня».
4. Расчёт минимальной и максимальной температуры, средней влажности,
   максимального ветра и описания ближайшей к полудню точки.
5. Сохранение в SQLite: новые записи вставляются, изменившиеся обновляются,
   одинаковые сохраняются без перезаписи. Город и дата уникальны на уровне БД.
6. Чтение сохранённых данных и создание основного отчёта по пути `OUTPUT_FILE`.

Основной отчёт содержит четыре даты текущего города. Дополнительно в `OUTPUT_DIR`
создаются отдельные отчёты с накопленной историей всех городов из БД.
Программа выводит город, координаты, даты, число вставленных и обновлённых записей,
число строк в отчёте и путь к файлу. Журнал записывается в `log/app.log`
с ротацией при размере 10 МБ и тремя резервными файлами.

Таймауты, отсутствие соединения, некорректные ответы, ошибки API 401/404/429,
ошибки БД и записи отчёта обрабатываются. При ошибке программа возвращает код 1.
Если API не содержит точек для одной из четырёх требуемых дат, программа сообщает
об отсутствии данных. Это возможно поздно вечером для сегодняшнего дня:
эндпоинт прогнозов возвращает будущие интервалы. Период не сдвигается автоматически.
Суточные показатели рассчитываются по доступным интервалам, поэтому сегодняшний
день может быть неполным.

## Пример отчёта

Значения ниже иллюстрируют формат и не являются реальным прогнозом.

```markdown
# Прогноз погоды

Суточный прогноз из OpenWeatherMap, агрегированный из трёхчасовых интервалов.

Автоматически определённая локация: Kirov
Период: 2026-10-04 – 2026-10-07

| Дата       | Мин. темп. (°C) | Макс. темп. (°C) | Описание   | Влажность (%) | Ветер (м/с) |
|------------|-----------------|------------------|------------|---------------|-------------|
| 2026-10-04 | 8               | 14               | Облачно    | 75            | 4           |
| 2026-10-05 | 6               | 13               | Дождь      | 85            | 5           |
| 2026-10-06 | 5               | 11               | Пасмурно   | 80            | 3           |
| 2026-10-07 | 7               | 15               | Ясно       | 70            | 2           |
```

## Структура проекта

```text
weather-etl-lab/
├── main.py                 # Последовательный запуск ETL и итоговый журнал
├── geo_locator.py          # IP-геолокация и резервный город
├── weather_client.py       # Запрос прогноза и суточная агрегация
├── db_models.py            # ORM-модель, сохранение и чтение SQLite
├── exporter.py             # Формирование Markdown-таблиц
├── core/
│   ├── __init__.py          # Общий пакет
│   ├── settings.py          # Загрузка .env и конфигурация
│   ├── logger.py            # Консольные и файловые логи
│   └── exceptions.py        # Ошибки погодного и географического API
├── tests/
│   └── test_pipeline.py     # Автономные проверки
├── .github/workflows/
│   └── tests.yml            # Проверки в GitHub Actions
├── .env.example            # Шаблон конфигурации
├── .gitignore              # Исключения из репозитория
├── requirements.txt        # Внешние зависимости
├── pyproject.toml          # Метаданные проекта и версия Python
└── README.md               # Установка, настройка и запуск
```

Файлы `.env`, `weather_lab.db`, `weather_report.md`, каталоги `data_weather/`,
`log/`, виртуальные окружения и кэши создаются локально и исключены из Git.
Каждый модуль отвечает за отдельный этап; настройки передаются явно,
а агрегация проверяется без обращения к сети.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют нужные календарные даты и часовой пояс, суточные показатели,
сохранение без дублей и лишней перезаписи, откат транзакций, резервную локацию,
сетевые ошибки, HTTP-коды, обработку ошибок БД и создание Markdown-файлов.
Используются временные БД и каталоги; рабочие `.env` и БД не изменяются.
Для GitHub Actions предусмотрены Python 3.11, 3.12 и 3.13.

## Публикация на GitHub

Создайте пустой репозиторий `weather-etl-lab` в GitHub. Выполните команды из корня
проекта, предварительно проверив, что `git status --short` показывает только код,
документацию, тесты и шаблон настроек:

```powershell
git add .
git diff --cached --name-only
git commit -m "Prepare weather ETL laboratory project"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/weather-etl-lab.git
git push -u origin main
```

Если `origin` уже настроен, проверьте адрес через `git remote -v` и используйте
`git remote set-url origin ...` при необходимости. Для новой папки без истории
перед этими командами выполните `git init`.

В список добавленных файлов не должны входить `.env`, базы, журналы,
сформированные отчёты или виртуальные окружения. `.env.example` должен входить
в репозиторий. После загрузки убедитесь, что GitHub Actions завершились успешно.
